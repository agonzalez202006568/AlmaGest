
# Registro de cambios y avances – AlmaGest

**Proyecto:** AlmaGest – Sistema de Gestión de Inventario  
**Asignatura:** Ingeniería de Software I  
**Responsable:** Aneurys González  
**Versión documental:** 0.1.0

## Objetivo

Documentar cinco avances relevantes realizados durante
la planificación, análisis, diseño y organización
técnica del proyecto AlmaGest.

## Historial de avances

### CAM-01 – Organización inicial del proyecto

**Etapa:** Semana II  
**Tipo:** Gestión del proyecto

Se creó el proyecto AlmaGest en GitHub Projects,
utilizando un tablero Kanban con cinco estados:

- Backlog
- Por hacer
- En progreso
- En revisión
- Finalizado

Se registraron seis tareas iniciales con sus
respectivas prioridades y responsables.

**Resultado:** Organización inicial del trabajo
y establecimiento de prioridades.

**Evidencia:** GitHub Projects e Issues #2 al #7.

---

### CAM-02 – Análisis y documentación de requisitos

**Etapa:** Semana III  
**Tipo:** Análisis de requisitos

Se elaboraron cinco historias de usuario
relacionadas con la gestión de inventario.

También se definieron requisitos funcionales
y no funcionales, junto con criterios
de aceptación y una tabla de trazabilidad.

**Resultado:** Definición de las necesidades
y funcionalidades principales de AlmaGest.

**Evidencia:** Issues #8 al #12 y documentación
ubicada en docs/requisitos/.

**Observación:** El levantamiento inicial se
realizó mediante una entrevista simulada
para fines académicos.

---

### CAM-03 – Planificación y seguimiento técnico

**Etapa:** Semana VI  
**Tipo:** Gestión técnica

Se incorporaron diez tareas técnicas
relacionadas con:

- Diseño de base de datos.
- Usuarios, roles y permisos.
- Gestión de materiales.
- Registro de entradas y salidas.
- Consulta de existencias.
- Validaciones.
- Historial de movimientos.
- Reportes.
- Pruebas funcionales.

Además, se identificaron cuatro riesgos
y sus respectivas acciones de mitigación.

**Resultado:** Ampliación del plan de trabajo
y definición de actividades técnicas.

**Evidencia:** GitHub Projects y matriz de riesgos.

---

### CAM-04 – Modelado y comunicación técnica

**Etapa:** Semana VII  
**Tipo:** Modelado y documentación

Se elaboró un diagrama de casos de uso
que representa los actores y las principales
funcionalidades del sistema.

También se identificaron los interesados
del proyecto y se preparó una matriz
de comunicación.

**Resultado:** Representación conceptual
del sistema y organización de la comunicación.

**Evidencia:** docs/uml/ y documentación académica
de comunicación con interesados.

---

### CAM-05 – Consolidación de documentación técnica

**Etapa:** Semana VIII  
**Tipo:** Documentación y control de versiones

Se actualizó el README.md principal y se
organizó la documentación del proyecto.

Se documentaron:

- Objetivo y alcance de AlmaGest.
- Funcionalidades principales.
- Requisitos.
- Arquitectura cliente-servidor.
- Organización conceptual del frontend.
- Organización conceptual del backend.
- Comunicación mediante API REST.
- Estado del proyecto y próximos pasos.

**Resultado:** Consolidación de la versión
documental inicial 0.1.0 de AlmaGest.

**Evidencia:** README.md y archivos de
docs/requisitos/, docs/uml/ y
docs/arquitectura/.

---

## Estado general

Los cinco avances corresponden principalmente
a análisis, planificación, modelado y
documentación técnica.

No representan cinco versiones ejecutables
ni implican que el software esté programado.

## Control de versiones

Los documentos almacenados en GitHub permiten
registrar su evolución mediante commits.

Los cambios posteriores deberán documentarse
con mensajes descriptivos y conservarse
en el historial del repositorio.
